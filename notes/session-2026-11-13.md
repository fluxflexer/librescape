## What was built

### 1. Publications (migration `005_editions.sql`)
- Naming:
  - The existing table `publication` holds **works**. The UI calls them "Works", and their item ids are `w<id>`.
  - The new table `edition` holds **publications**: books, collections, anthologies, journals, magazines, other. The UI calls them "Publications", their item ids are `x<id>`, and their deep link is `#edition-<id>`.
- Tables:
  - `edition_editor`: the editors of a publication.
  - `edition_work`: links works to publications, many-to-many. Each link has a locator (e.g. "pp. 38–89"), a "first publication" flag and a sort order.
  - `edition_keyword`: keywords on publications.
  - The `weblink`, `source_ref` and `image` tables now accept `edition` as an entity type.
- Rules:
  - A work can appear in several publications.
  - Only one publication per work can be marked as its first publication. This is checked from both sides.
  - Like every entry, a publication needs a source.
- Admin:
  - A "Publications" page with a list, an edit form (publication data, contents, editors) and a quick-create dialog.
  - The work form has a "Published in" block.
- Viewer:
  - The details panel has a "Published in" section for works and a "Contents" section for publications.
  - Search finds publications.
- Example entry: "Essays Presented to Charles Williams" (1947, OUP, edited by C.S. Lewis). It contains *On Fairy-Stories* on pp. 38–89 and is that work's first publication.

### 2. Lanes
- Works are drawn in the **Works** lane, with a diamond marker.
- Publications are drawn as points in the **Publications** lane.

### 3. Work date means "Started"
- The work date (column `release_date`, which keeps its name) is labelled "Started" throughout the admin app and the viewer.
- Open question: the demo data still holds publication dates in this field. They could be moved into publication entries.

### 4. Admin dropdowns
- "+ Create new…" / "+ New …" are now the first entries in every dropdown.
- Recently used choices come right below them, marked with ↺. This covers sources, persons, works, lanes, categories, relation kinds and publication kinds.
- The last 3 choices are stored per kind in the browser's localStorage, so each browser has its own list.

### 5. Pictures fetched on save
- Saving an entry fetches its Wikipedia picture straight away. The code is in `lib/images.php`, shared with `tools/fetch_images.php`.
- The save message tells you whether a picture was stored, removed or not available under a free licence.
- `deploy.ps1` no longer deletes fetched pictures: `media` is copied rather than mirrored.
- `.\deploy.ps1 -FetchImages` fetches pictures for every entry.
- Pictures are not part of the DB backups.

### 6. Viewer fixes
- Line breaks in descriptions are kept: press Enter in the admin text box.
- The page can no longer be scrolled sideways. The empty space on the right was coming from the hidden details panel.
- A footer bar with a short usage hint marks the bottom edge of the page.
